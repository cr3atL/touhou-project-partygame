# 幻想乡巡游

东方角色主题的四人飞行棋，七名角色各有一个主动和被动技能。支持本机 1～4 位玩家与机器人配置，以及在线四人房间。

[打开游戏](https://cr3atl.github.io/touhou-project-partygame/) · [下载版本](https://github.com/cr3atL/touhou-project-partygame/releases) · [更新日志](CHANGELOG.md)

当前版本 **v0.1.61**（2026-10-27）。游戏仍在持续调整，欢迎通过 Issue 反馈玩法和平衡问题。

## 开始游玩

- **本机游玩**：四个固定席位各自选择玩家或机器人；一名玩家加三名机器人也在这里配置。
- **四人房间**：创建房间并分享房间号，其他玩家输入房间号加入。选角和准备完成后，由房主开始；空位可用机器人补齐。
- **基本操作**：开局各席掷骰，按点数从大到小决定行动顺序，平点继续重掷。席位编号与顶部排列始终固定。回合内掷骰后选棋，查看完整路线与撞击等结果，再点击“确认移动”；可以改选或取消。棋盘支持拖动、缩放和手机双指操作。

标题菜单提供开始游戏、继续游戏、游戏介绍、设置及关于游戏；没有可继续的存档时，继续入口置灰。点击玩家头像查看技能、冷却与棋子详情。对局菜单提供设置与返回标题，本机打开时暂停，联机仍继续进行。巡游记录收起时显示最近一条，展开可按回合查看。

整局计时位于回合数附近，包含开局掷骰与演出时间，扣除本机暂停时间；读档后继续累计，离线时间不计入。旧存档未记录整局时长时，从恢复后的零点开始累计。标题与大厅支持鼠标移入及键盘焦点选择音、点击确定音和返回退出音，手机点击不叠加选择音；对局内不触发悬停或焦点选择音。

标题与大厅使用 ajapa 的「少女奇想天外曲」。对局随机轮播「恋色ジャズタイム」「チルノの日常」「椛の日常」「向日葵's Coffee」「魔法の森のカフェ」「紅茶を飲みましょう」六首：每轮各播放一次，播完重新随机排列，轮次交界处也不会连续重复同一首；曲目完整播放，首尾轻柔淡入淡出。标题进入大厅、对局内切换玩家及打开菜单均保留播放进度和待播顺序。浏览器首次交互后开始播放，切到后台时暂停音乐并保留进度。设置可分别开关和调节音乐、音效。

标题封面采用已确认的灵梦派对构图，背景铺满窗口，棋子、骰子与符卡独立漂浮；更新日志位于“关于游戏”。客户端与房间服务需同时更新至协议 6。本地可迁移同地图的 v0.1.5 存档，保留原有席位、行动顺序与剩余时间；旧地图存档继续保留但不兼容。

## 对局规则

每人控制四枚棋子，四枚全部完成后按顺序获得名次并退出行动。决出前三名后整局结束，剩余玩家为第四名。

- 任意骰点均可出场，消耗该次行动，先停在独立出场格；下一次骰子行动再进入主路。出场不撞击或触发加速。
- 落在己方颜色时自动跳格；抵达专属航线入口自动飞行，飞行结束后可再跳一次。普通途经格不撞击，航线可以撞击所经过的终点道交叉格。
- 同一撞击位置的全部敌棋先处理保护，再按实际撞毁数结算；撞毁两枚及以上时同归于尽，进攻棋子的保护可以抵消返航。航线交叉格与最终落点分别计数。
- 终点必须精确到达，步数超过时先到终点再折返。
- 自然六点追加行动，不刷新回合时间或技能次数；连续第三个自然六点取消行动，让上一次骰子行动移动的棋子返航并结束回合。保护可以抵消返航，已完成的棋子不受影响。
- 每回合共用 **60 秒**决策时间，不可操作的演出期间暂停扣时。最后 5 秒播放倒计时音效；超时后机器人完成本回合，下回合恢复玩家控制。

角色技能和冷却可在主页及对局符卡面板查看。技能额外位移不撞击、不触发跳格或航线，也不能直接进入终点道。

## 在线房间

房间服务部署在 Render。免费实例休眠后，首次连接可能等待约一分钟。异常断线保留席位 120 秒；主动离开或超过重连时间后由机器人接管。服务重启或重新部署后，内存中的房间不会保留。

网页与房间服务需要使用匹配的规则和协议版本。升级期间若提示版本不兼容，请等待房间服务更新后刷新网页。

## 本地开发与验证

需要 Node.js 22 或更新版本，建议使用 24。

```sh
npm ci
npm run dev
```

打开 `http://localhost:5173`。启动时会显示局域网地址。

```sh
npm test
npm run build:server
npm run test:rooms
npm run test:network
npm run test:decision-network
npm run test:room-management
npm run build
npm run check:release
```

`node scripts/generate-board.mjs` 从同一组坐标生成地图数据及桌面、手机两套 SVG。测试场景和模拟工具仅位于 `tests/helpers/`，不提供网页或房间调用入口。

## 部署

推送 `main` 后，GitHub Actions 会运行测试、构建与发布检查，再部署 GitHub Pages。网页使用仓库变量 `VITE_ROOM_SERVER_URL` 指定公开的 `wss://` 房间地址，构建时自动适配仓库子路径。

Render 使用仓库中的 `render.yaml` 构建房间服务，检查通过后自动部署。手动运行 `npm run build:server` 后可用 `npm start` 启动服务；`GET /health` 返回健康、规则与协议版本，不提供调试或改写状态接口。

东方 Project 相关角色属于原作者。标题封面采用 schwarz 灵梦模型的常规渲染，背景为不含角色的 AI 图像，飞行骰子、棋子与符卡独立分层；仅渲染图进入网页，原始模型保留本地。素材来源见 [public/cover/sources.json](public/cover/sources.json) 与 [public/audio/sources.json](public/audio/sources.json)。
